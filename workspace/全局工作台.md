# 全局工作台

**定义**：工作系统的规则中枢，一切规则的总入口。

**解决**：文档散落、命名混乱、行为无红线、产出不可追溯。

**目标**：让所有工作有章可循，产出可追溯，方向不偏航。

### 1.1 目录结构

```
<WORKSPACE_ROOT>/
├── Workspace/　　　　   ← 规则中枢（六份核心文档，不存项目产出）
├── Project-001-名称/　　← 具体项目（编号自增）
│   ├── 背景情况.md　　　 ← 必填，项目启动前由用户提供
│   ├── Token成本核算.md ← 项目收尾统计
│   └── ...　　　　　　　 ← 该项目全部产出
├── Project-002-名称/
└── ...
```

约束：所有项目文件**必须**存入对应项目文件夹，禁止散落到桌面、下载等其它路径。

### 1.2 核心文档职责

| 文档 | 职责 |
|------|------|
| `agent.md` | Agent 最高优先级指令 |
| `全局工作台.md` | 总体规则、目录规范、行为铁律、命名规范、执行原则 |
| `复利与踩坑.md` | 记录错误、教训、可复用方法，避免重复踩坑 |
| `新项目流程.md` | 标准化项目启动流程，从需求到交付 |
| `工程的原则.md` | 代码/工程任务的执行基线 |
| `方法论日志.md` | 方法论的版本演变记录 |

### 1.3 行为铁律（11 条）

1. 不得在未创建项目文件夹的情况下开始任何实质性工作。
2. 每开启一个新任务，必须先执行 `新项目流程.md` 中的流程。
3. 所有产出、中间文件、笔记，必须进入对应项目文件夹。
4. 项目完成后，必须更新 `复利与踩坑.md`，沉淀经验。
5. 使用 `blindspot-audit` 在关键节点扫描盲区，并补充到方案中。
6. 项目收尾必须完成 Token 成本核算，记录到 `Token成本核算.md`。
7. 交付后提供修订窗口：用户可在交付后 48 小时内提出修订需求，免费修订一轮。
8. 每次 Workspace 核心文档修改后，自动同步更新 `实时日期+SIWFA工作区行为规范备份.md`。
9. 项目启动前必须执行技能策展：检索本地技能库和技能清单表 → 查外部平台有无更好替代 → 择优汰旧。
10. 涉及代码/工程实现类任务时，进入「执行」阶段前必须先读 `工程的原则.md` 并遵循其原则。
11. 向用户输出的汇报默认遵循 STE 规范（详见 `agent.md` 的「汇报规范」）。

### 1.4 命名规范

- 项目文件夹：`Project-三位数字编号-项目名称`（连字符分隔），如 `Project-001-官网改版`
- 编号连续递增，不重复。
- 文件命名：简洁描述，用下划线或中划线，如 `需求分析_v1.md`

### 1.5 通用执行原则（8 条）

1. **杜绝主观臆断**：不猜测用户意图，不确定时追问确认。
2. **分层递进收拢需求**：从模糊到清晰，逐层确认。
3. **先预览再选择**：交付物先出预览，用户选定后再出完整版。
4. **以交付成果为核心导向**：不产出与交付无关的中间内容。
5. **可随时回退**：流程偏差时退回上一环节重新确认。
6. **全程中文沟通**。
7. **框架提问全部多选题**：提供选项供用户勾选。
8. **理解日志全部数字选择题**：1-N 序号，用户答数字。
